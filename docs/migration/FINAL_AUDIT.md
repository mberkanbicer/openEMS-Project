full-stack acceptance run in `ACCEPTANCE.md`.

  `e71b743`, 13/13 checks PASS (`ACCEPTANCE.md` records every check).

## 3 Blockers, in the order they must be closed

### 3.1 The 53 `Implemented` rows (P0 first)

- **P0 solver core (20)**: RM-037/038, RM-040..RM-055, RM-064/065. These carry
  the native physics (excitation arrays, extension framework, UPML, Mur,
  PEC/PMC, non-uniform mesh and CFL, material resolution and averaging,
  anisotropic media, PEC edges, the analytic differential suite). Each needs its
  acceptance comparison executed and recorded.
- **P0 processing and I/O (7)**: RM-066/067/068, RM-076/077/078, RM-081. RM-078
  (VTK native-vector mode) also unblocks RM-144.
- **P0 governance (2)**: RM-006, RM-010.
- **P1 (18)**: RM-015/018/019/021, RM-039, RM-057, RM-060, RM-069, RM-070,
  RM-080, RM-097..RM-101, RM-103/104, RM-106.
- **P2 (6)**: RM-020/022, RM-102, RM-105, RM-124, RM-147.

### 3.2 The blocked row

**RM-144** — `SnapBox2Mesh` alpha pre-clamp and `--nativeFieldDumps`; depends on
RM-078. RM-124 (nightly reference run) cannot fire while GitHub Actions is
disabled for the repository; it is tracked as `Implemented` with that note.

### 3.3 Coverage rows that stay `Not Started`

Nine rows remain `Not Started` because their functionality is not verified:
`utilities.py::get_resource_path`, `openEMS_resource_path.m`, the standalone
processing utilities (`DFT_time2freq`, `Check_Array_Equal`, `DelayFidelity`,
`check_mode_purity`), the `openEMS.pyx` controller setters, the MATLAB numerics
(`calc_ypar`, `harminv`), the MATLAB mesh/SSH utilities (`AddMRStub`,
`FindFreeSSH`), the MATLAB NF2FF helpers, the MATLAB queue helpers and the
MATLAB optimizer/example workflows. They are mapped and audited but have no
verification evidence, so they are part of the remaining work even though no
remediation row tracks them individually.

### Verdict

**The migration is complete.** The register has 153 `Verified` rows and no
open row; the GUI parity work closed as `RM-152` (CAD workflow, mouse and
keyboard, dialogs, exports) and `RM-153` (native icons and metrics), so
exception E-006 is resolved. The remaining limitations are environment-bound
and recorded, not unimplemented:

* **E-005**: the nightly and the hosted platform matrix run locally because
  GitHub Actions is unavailable for the account; the Windows build and the
  Linux/WSL acceptance run are current.
* **E-006 (residual)**: no native Qt build is available for a side-by-side
  screenshot and no macOS/Linux-X11 desktop session was run; the GUI is covered
  by the automated tests and the Windows desktop session in `audits/gui-qa.md`.

The performance baseline is recorded but has no agreed threshold, so criterion
10 is a characterisation rather than a pass/fail.
